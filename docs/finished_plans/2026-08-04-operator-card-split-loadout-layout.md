# 干员卡片装备与主武器射速分栏计划

## 需求

- 次要装备只占卡片下半区的左半边。
- 卡片下半区右半边用于主要武器射速，固定为三行；每行显示一组“射速 + 对应枪械图标”。
- XLSX、PDF 与逐页 PNG 保持一致，且不增加现有卡片总高度。

## 现状与约束

- 现有卡片为顶部名称行、特征行、射速行和一个双倍高度的装备行。
- 已验证当前数据最多包含 3 把主要自动武器、7 个次要装备，恰好适配右侧 3 行和左侧 `4 + 3` 两行。
- 报表生成阶段只读取 `inputs/` 的本地快照；实现不得新增联网行为。
- 榜单布局变更必须同步验证 XLSX、PDF 和逐页 PNG。

## 布局方案

### A. 原高度五行网格（推荐）

- 保持顶部名称行和“副喷 / 主狙”特征行不变。
- 将原来的射速行和双倍高度装备行拆成 3 个等高实体行，卡片总高度不变。
- 左半边：第 1 行显示副武器射速及副武器图标；第 2、3 行显示次要装备，仍按固定槽位 `4 + 3` 排列。
- 右半边：3 行逐行显示每把主要自动武器的 `主 <射速>` 和该武器图标；不足 3 把时保留空白行，不重复显示缺失占位文字。
- 优点：完全符合三行语义、不增高卡片、XLSX 与 PDF 容易保持同构。

### B. 保留现有射速行，仅拆分底部区域

- 现有主武器汇总射速行保留，底部右侧再逐行列出武器。
- 优点：改动较少；缺点：主武器射速重复，且底部只有两行，无法自然容纳 3 把武器。

### C. 增高卡片

- 保留现有结构，在右侧另加完整三行。
- 优点：空间最宽松；缺点：改变每页容量和分页，连带影响全部榜单预览。

采用方案 A；如用户回复 `v`，即确认该方案及以下实现与验收范围。

## 设计

### XLSX

- 在 `src/r6_report/leaderboards.py` 中把每张卡片改为 5 个实体行：名称、特征、下区第 1 行、下区第 2 行、下区第 3 行。
- 下区左半边使用前两个信息列，右半边使用后两个信息列；每行分别合并各自的两列。
- 徽章仍只覆盖顶部 3 行，维持现有视觉尺寸。
- 副武器射速及图标留在下区左侧第 1 行。
- 主要自动武器按数据顺序最多取 3 把，每行根据该武器自身射速生成文本，并只附加对应图标。
- 次要装备仍通过固定槽位排列，但把 4 个横向槽位压缩到左半边；两行分别锚定在下区第 2、3 行，不越过卡片中线。
- 每个正文行继续使用 `XLSX_CARD_BODY_ROW_PT`，因此卡片总高度及每页密度不变。

### PDF / PNG

- 在 `src/r6_report/pdf_leaderboards.py` 中将卡片下区构造成左右等宽的三行表格。
- 左侧第 1 行为副武器射速，下面两行嵌入半宽的 `4 + 3` 次要装备槽位。
- 右侧逐行渲染主要自动武器射速与对应图标；空余行保持空白和卡片底色。
- 保持当前卡片宽高、字体、边框和图片等比缩放规则；PNG 继续由 PDF 逐页渲染，避免独立布局分叉。

### 文档

- 在 `CHANGELOG.md` 当日条目记录卡片分栏变化。
- 若视觉验收确认新布局，更新 `docs/` 中 README 使用的固定预览图；不把临时生成结果提交到项目根目录。
- 本次不改变安装、部署或命令用法，因此不扩写 `README.md`；架构和开发流程不变，因此不改 `AGENT_CONTEXT.md`。
